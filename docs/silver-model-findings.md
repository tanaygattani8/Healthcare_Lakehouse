# Silver model — what the data actually contains

Measured locally with DuckDB against `synthea/output/csv/` before writing any
silver code. Phase 2a Task 2.

Written by hand, unlike `calibration.md`, which is generated by
`scripts/calibrate.py` and must not be edited.

**Four of these findings contradict the phase 2 spec.** The spec was written
before anyone looked at the files.

---

## 1. One file does not mean one codebook

The spec assumes four vocabularies in four files. Wrong on both halves.

| File | Has `SYSTEM` column? | Values found |
|---|---|---|
| `conditions` | yes | `http://snomed.info/sct` — 111,881 rows |
| `procedures` | yes | `http://snomed.info/sct` — 575,050 rows |
| `allergies` | yes | `SNOMED-CT` — 916 rows, **`RxNorm` — 102 rows** |
| `observations` | no | — |
| `medications` | no | — |
| `immunizations` | no | — |

Two consequences:

**`allergies` is a mixed table.** It holds SNOMED *and* RxNorm codes — an
allergy to a substance and an allergy to a drug are coded in different systems.
Any rule of the form "rows from this file are SNOMED" is wrong for 102 rows.
Those rows would be filed under the wrong codebook and silently join to the
wrong `dim_code` entries.

**The same codebook is named two ways.** `conditions` and `procedures` say
`http://snomed.info/sct`; `allergies` says `SNOMED-CT`. Both mean SNOMED CT.
`dim_code` must normalise these to one value, or SNOMED appears twice as two
unrelated systems.

Three files state their codebook and three do not, so `dim_code` needs two
paths: read `SYSTEM` where it exists, assign a constant where it does not.

## 2. `procedures` is a genuine fifth source

- `conditions`: 271 distinct codes
- `procedures`: 380 distinct codes
- **Codes in common: 0**

Both are SNOMED, and they do not overlap at all. Leaving `procedures` out of
`dim_code` — which the spec's four-source table does — loses 380 codes, more
than any other single source contributes.

Counting sources properly: SNOMED from `conditions`, `procedures` and part of
`allergies`; LOINC from `observations`; RxNorm from `medications` and the rest
of `allergies`; CVX from `immunizations`. Six file-to-system paths, four
systems.

## 3. Codes with two descriptions are real, not hypothetical

| File | Ambiguous codes |
|---|---|
| `conditions` | none |
| `procedures` | none |
| `allergies` | none |
| `observations` | `6299-2`, `8310-5` — 2 descriptions each |
| `medications` | `312961`, `1000126`, `1049221` — 2 each |
| `immunizations` | `133`, `114`, `115` — 2 each |

A `dim_code` keyed on (system, code) **will** hit a duplicate key without a rule
for choosing the description. Pick one — most frequent, first seen, longest —
and record it. This is not an edge case to defend against later; it is present
in the current dataset.

## 4. 150,120 observations have no encounter

Empty `ENCOUNTER` on 150,120 of 2,223,785 observation rows — **6.75%**.

This is the single most consequential finding for Task 7. An expectation
requiring every observation to resolve to a real encounter would quarantine
150,120 rows on a dataset with nothing wrong with it. The foreign key to
encounter has to be optional, and the expectation has to be written against
patient rather than encounter.

Getting this backwards produces a quarantine table with 150k rows in it and a
day spent looking for a bug that is not there.

## 5. Nothing else fails to parse — which is itself a problem

| Check | Failing rows |
|---|---|
| `patients.BIRTHDATE` not a date | 0 |
| `patients.DEATHDATE` present but unparseable | 0 |
| `encounters.START` not a timestamp | 0 |
| `encounters.STOP` before `START` | 0 |
| `observations.VALUE` not numeric where `TYPE` says numeric | 0 |
| conditions/observations/medications/procedures pointing at a missing patient | 0 |

Synthea generates *mostly* internally consistent data. Every type casts, every
date orders correctly in the columns checked above, every foreign key resolves.

**Correction, found after the silver build ran.** The check above tested
`encounters` for `STOP` before `START` and did not test `medications`.
**104 medication rows have a stop date six days before their start date** — for
example an insulin prescription starting 1978-08-22 and stopping 1978-08-16.
They are quarantined, correctly, and they are the only rows in the entire
quarantine layer.

The lesson is about the measurement, not the data: a clean result is only as
broad as the checks written, and "nothing fails" was reported after checking one
table for a rule that applies to five.

**One consequence stands.** With 104 rows out of 3.28 million failing, the
quarantine tables are nearly empty — and a nearly empty quarantine table is hard
to distinguish from a mechanism that does not work. Breaking a row deliberately
and watching it arrive is still worth doing.

## 6. Ten encounter classes, not the five the spec names

| Class | Count |
|---|---|
| ambulatory | 102,654 |
| wellness | 47,829 |
| outpatient | 21,140 |
| emergency | 7,538 |
| urgentcare | 5,292 |
| **inpatient** | **1,292** |
| home | 714 |
| snf | 625 |
| virtual | 265 |
| hospice | 191 |

The spec lists ambulatory, emergency, inpatient, wellness and urgentcare. The
data also has `outpatient`, `home`, `snf` (skilled nursing facility), `virtual`
and `hospice` — 1,795 encounters, small but not zero.

`inpatient` = 1,292 matches `docs/readmission-gate.md` exactly, which confirms
the gate and this measurement are looking at the same population.

**The three-way mapping needs a decision for the five classes the spec never
considered.** Suggested, with reasoning, but this is a clinical judgement call:

| Class | Suggested | Why |
|---|---|---|
| inpatient | acute | Admitted to hospital |
| emergency | acute | Unplanned, urgent |
| urgentcare | acute | Unplanned |
| snf | acute? | Post-acute care. Often *follows* a discharge, so counting it as a readmission would be wrong |
| hospice | acute? | End of life. Almost certainly must be **excluded** from readmission denominators, not merely classified |
| home | ambulatory | Home health visit |
| ambulatory | ambulatory | |
| outpatient | ambulatory | |
| virtual | ambulatory | Telehealth |
| wellness | preventive | Check-ups |

**`snf` and `hospice` are the ones that matter.** CMS readmission methodology
generally excludes hospice, and transfers to skilled nursing are not
readmissions. Getting these wrong changes the phase 4 number. Decide
deliberately and record the reasoning.

1. Task 3 reads `SYSTEM` where present and normalises `http://snomed.info/sct`
   and `SNOMED-CT` to one value
2. Task 3 splits `allergies` by its `SYSTEM` column rather than assuming
3. Task 3 includes `procedures` — 380 codes that would otherwise be lost
4. Task 3 needs a tie-break rule for descriptions, because duplicates exist now
5. Task 7's encounter foreign key on `observation` must be optional
6. Task 4 must map ten values, and two of them are genuine clinical decisions
